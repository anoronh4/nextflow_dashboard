# Split the dashboard into readable source files

**Date:** 2026-11-13
**Status:** Approved design, pending implementation plan

## Goal

Make the dashboard's code easy for a person to read and edit, without changing what it does and
without losing either way of using it offline:

- **Editing:** readable source split across focused files, which run directly in a browser from
  `file://` with no build step.
- **Sharing:** the existing single self-contained `pipeline_dashboard_offline.html` stays at the
  repo root under the same name, generated from the source.

## Non-goals

- No behaviour changes. In particular, these stay as they are: the Typical Sample stats cache that
  can go stale between tabs, `getTasks` re-filtering all runs on every render, and per-chart quirks.
  They stay listed under "Known rough edges" in CLAUDE.md.
- No frameworks, package managers, ES modules or network dependencies.
- No git hooks. The repo already runs tacet's hooks; the sync check is a manual command.

## Constraints

- **Offline from `file://`.** Browsers load classic `<script src>` and `<link rel=stylesheet>`
  from `file://` but refuse ES modules (`import`/`export`). The source therefore uses plain
  scripts that share globals, exactly as the inlined code does today. This also keeps the inline
  `onclick="…"` handlers in the HTML working unchanged.
- **Vendored libraries are copied byte-for-byte** from the current file (Plotly 2.26.0,
  Bootstrap 5.3.2 CSS and JS bundle). They are never edited or minified again.

## Layout

```
pipeline_dashboard_offline.html   GENERATED single-file bundle (for sharing; never hand-edited)
build.py                          src/ → pipeline_dashboard_offline.html; --check verifies sync
src/
  index.html                      markup only, then <script> tags in load order
  css/app.css                     hand-written CSS (+ .toggle-btn classes, see Cleanups)
  vendor/
    plotly.min.js
    bootstrap.min.css
    bootstrap.bundle.min.js
  js/
    state.js                      global `state` object; each field documented
    parse.js                      parseTrace + unit normalisation (parseTS, parseDurMs, parseMemB,
                                  extractSample, shortProc)
    format.js                     fmtBytes, fmtHours, arrMedian, arrQuantile
    colors.js                     PALETTE, DISTINCT_PALETTE, sampleColor, processColor
    plot.js                       shared Plotly theme, plot(), large-text PNG export
    filters.js                    toggleStatus, isRealSample, Processes filter, getTasks
    anonymize.js                  aliases, sampleLabel/runLabel, renderIdLabels, toggleAnonymize
    charts/
      concurrency.js              shared event-sweep helper + 4 concurrent CPU/memory charts
      timeline.js                 Job Timeline (Gantt)
      sample-table.js             Sample Breakdown table + sortBy
      durations.js                Process Durations + order/colour toggles
      efficiency.js               CPU and Memory Efficiency
      typical.js                  Typical Sample: stats, cards, scatter, table, TSV export
      queue.js                    Queue Wait
    app.js                        file loading, drag-and-drop, switchTab, updateAll,
                                  renderActiveTab, metric cards; all top-level listener setup
```

**Load order** in `index.html`: vendor scripts, then `state`, `parse`, `format`, `colors`, `plot`,
`filters`, `anonymize`, `charts/*`, and `app` last. Most files only declare functions and constants,
so order matters only for top-level statements. Those (event listener setup, the document click
handler for the Processes panel) move into `app.js` so they run after everything is defined.

**File headers:** each JS file starts with 2–4 comment lines saying what it owns and which globals
from other files it relies on. These are added in cleanup 4, so the move commit stays a pure move
(code moved verbatim; only the top-level listener setup changes files).

**Adding a tab:** a new `charts/foo.js`, plus in `index.html` a `<script>` tag, the tab button and
the pane, plus one branch in `renderActiveTab` in `app.js`.

## Build (`build.py`)

- Python 3 standard library only.
- `python3 build.py`: reads `src/index.html`. Each `<link rel="stylesheet" href="…">` pointing
  into `src/` becomes an inline `<style>` with that file's contents, and each `<script src="…"></script>`
  becomes an inline `<script>`, in document order. Writes `pipeline_dashboard_offline.html`.
- `python3 build.py --check`: builds in memory, compares with the committed bundle, exits non-zero
  with a one-line message if they differ.
- The bundle starts with `<!-- GENERATED by build.py from src/ — edit src/, then run python3 build.py -->`.
- Each inlined block is preceded by a comment naming its source file (`/* ── src/js/charts/timeline.js ── */`),
  so errors in the bundle can be traced back to a file.
- Output is deterministic: same `src/` → same bytes.

## Cleanups (after the move, one commit each)

1. **Shared event sweep.** The step-function sweep (emit +x at start, −x at complete, sort, record
   the running total before and after each timestamp) is currently written out in about six
   places: allocated CPU, actual CPU, peak RSS, allocated memory, Queue Wait pending tasks,
   and per-sample peaks in Typical Sample. Replace them with one documented helper in
   `charts/concurrency.js`, which each caller gives intervals and a per-task value. Output must
   be identical point for point.
2. **Remove dead state:** `state.sortKey` and `state.sortDir`. The sample table uses the module-level
   `sortKey`/`sortDir`.
3. **Inline button styles to CSS.** The Process Durations order/colour buttons and the Typical
   Sample `write_bytes`/`wchar` buttons get a `.toggle-btn` / `.toggle-btn.active` class pair in
   `app.css`, replacing their `style="…"` attributes and the JS that sets background/colour per
   property. Rendering must look identical.
4. **Accurate headers.** Replace the misnumbered section titles ("CHART 3" twice, "CHART 4" twice,
   "CHART 7") with plain names, and add the per-file headers above.

## Verification

There is no test suite, so use a before/after snapshot comparison in Chrome with the demo traces
in `examples/`:

1. **Baseline (before any change)** from the current `pipeline_dashboard_offline.html`, with both
   demo traces loaded. States:
   - every tab, default filters
   - Run filter = demo-run-1
   - Processes filter narrowed to 3 processes
   - Status with Cached excluded
   - Anonymize on
   - Process Durations order and colour set to A→Z
   - Typical Sample "written" = `wchar`

   For each state, record:
   - every chart's Plotly `data` and `layout`
   - the tables' `innerHTML`
   - the metric cards' text
   - the toolbar button titles

   Also record one dark and one light large-text export per chart (hash of the PNG bytes), and
   the Typical Sample TSV text.
2. **After the move:** the snapshot from `src/index.html` and from the rebuilt bundle must both
   equal the baseline exactly.
3. **After each cleanup:** same exact comparison. For the toggle-button cleanup, which changes the
   markup, also compare screenshots side by side.
4. **Also:** no console errors on any tab; `python3 build.py --check` passes; the page works with
   networking disabled.

The snapshot script is a one-off in the session scratch folder, not committed.
